<objective>
Build the production multi-stage Docker containerization, cross-platform launcher scripts, and Playwright end-to-end (E2E) testing suite for the FinAlly AI Trading Workstation.

This plan covers:
1. Multi-stage `Dockerfile` (Stage 1: Node 20 static export build; Stage 2: Python 3.12 runtime serving Uvicorn) and `docker-compose.yml` with host volume bind mount `./db:/app/db` (**DOCK-01** / DOC-01).
2. Static asset mounting in FastAPI `backend/app/main.py` serving static files at root `/` via Starlette `StaticFiles` while preserving precedence for `/api/*` routes (**DOCK-01** / DOC-01).
3. Cross-platform launcher automation scripts (`scripts/start_mac.sh`, `scripts/stop_mac.sh`, `scripts/start_windows.ps1`, `scripts/stop_windows.ps1`) with Docker status verification, host `./db` directory creation, active HTTP `/api/health` polling, and default browser launch (**SCR-01** / DOC-02).
4. Playwright E2E testing framework (`test/e2e/playwright.config.ts`, `test/e2e/trading.spec.ts`) and containerized test runner (`docker-compose.test.yml`) validating live SSE streaming, market trade execution, watchlist modifications, and AI copilot actions (**TEST-01**).
5. Comprehensive end-to-end build, container health, and test suite verification.
</objective>

- .dockerignore
</files>
<step>
Create the multi-stage Dockerfile and Docker Compose configuration for unified single-container deployment of Next.js frontend static export and FastAPI backend server.
</step>
<details>
1. Create `.dockerignore` to exclude unneeded source assets and build artifacts:
   - `.git`, `node_modules`, `.next`, `frontend/out`, `backend/.venv`, `backend/__pycache__`, `*.db`, `.env`.

2. Create `Dockerfile`:
   - **Stage 1 (`frontend-builder`)**:
     - Base image `node:20-alpine`. Set `WORKDIR /app/frontend`.
     - Copy `frontend/package.json` and `frontend/package-lock.json` (if exists), run `npm ci`.
     - Copy `frontend/` source code and execute `npm run build` (outputs static files to `/app/frontend/out`).
   - **Stage 2 (`runner`)**:
     - Base image `python:3.12-slim`. Set `WORKDIR /app`.
     - Environment variables: `PYTHONUNBUFFERED=1`, `PYTHONDONTWRITEBYTECODE=1`, `PORT=8000`, `DB_PATH=/app/db/finally.db`.
     - Install system dependencies (`curl`) and `uv` package manager (`pip install --no-cache-dir uv`).
     - Copy `backend/pyproject.toml`, `backend/README.md` (if exists), and `backend/app`.
     - Execute `WORKDIR /app/backend && uv pip install --system -e .`.
     - Copy static frontend output from Stage 1 into FastAPI static directory: `COPY --from=frontend-builder /app/frontend/out /app/backend/app/static`.
     - Expose port `8000`.
     - Set default entrypoint command: `CMD ["uvicorn", "app.main:app", "--host", "0.0.0.0", "--port", "8000"]`.

3. Create `docker-compose.yml`:
   - Service `finally-app` with build context `.`, dockerfile `Dockerfile`, container_name `finally-app`.
   - Forward port `8000:8000`.
   - Host volume bind mount `./db:/app/db` ensuring SQLite persistence.
   - Inject environment variables: `LLM_MOCK=${LLM_MOCK:-true}`, `OPENROUTER_API_KEY=${OPENROUTER_API_KEY:-}`, `MASSIVE_API_KEY=${MASSIVE_API_KEY:-}`, `DB_PATH=/app/db/finally.db`.
   - Healthcheck block testing `curl -f http://localhost:8000/api/health` with 5s interval, 3s timeout, 5 retries.
   - Restart policy `unless-stopped`.
</details>

<task id="05-01-03" type="expansion">
<name>Cross-Platform Start/Stop Automation Launcher Scripts (SCR-01 / DOC-02)</name>
<files>
- scripts/start_mac.sh
- scripts/stop_mac.sh
- scripts/start_windows.ps1
- scripts/stop_windows.ps1
</files>
<step>
Implement zero-friction cross-platform start and stop scripts for macOS/Linux (`.sh`) and Windows (`.ps1`) environments with Docker validation, directory creation, health check polling, and browser launch.
</step>
<details>
1. Create `scripts/start_mac.sh`:
   - Bash script (`#!/usr/bin/env bash`, `set -e`).
   - Dynamically resolve project root using `PROJECT_ROOT="$(cd "$(dirname "${BASH_SOURCE[0]}")/.." && pwd)"`.
   - Verify Docker daemon status via `docker info > /dev/null 2>&1`. Output clear user diagnostic message and exit 1 if Docker is stopped.
   - Ensure host database volume directory exists (`mkdir -p db`) prior to compose invocation to prevent Docker daemon from creating root-owned `./db`.
   - Execute `docker-compose up -d --build`.
   - Poll readiness by looping `curl -s -o /dev/null -w "%{http_code}" http://localhost:8000/api/health` up to 30 attempts with 1-second delay.
   - Upon HTTP 200 response, automatically launch default web browser (`open http://localhost:8000` on macOS or `xdg-open http://localhost:8000` on Linux).
   - Dumps container log output (`docker-compose logs --tail=50`) on timeout and exits with error code 1.

2. Create `scripts/stop_mac.sh`:
   - Bash script (`#!/usr/bin/env bash`, `set -e`).
   - Resolves project root and executes `docker-compose down` with success notification.

3. Create `scripts/start_windows.ps1`:
   - PowerShell script (`$ErrorActionPreference = "Stop"`).
   - Resolves project root `$ProjectRoot = Resolve-Path "$PSScriptRoot\.."`.
   - Checks Docker status via `docker info`.
   - Ensures `db` host folder exists (`New-Item -ItemType Directory -Path "db"`).
   - Runs `docker-compose up -d --build`.
   - Polls `http://localhost:8000/api/health` using `Invoke-RestMethod` (max 30 attempts, 1s sleep).
   - Launches browser using `Start-Process "http://localhost:8000"`.
   - Dumps logs and exits on error.

4. Create `scripts/stop_windows.ps1`:
   - PowerShell script executing `docker-compose down`.

5. Ensure file permissions (`chmod +x scripts/start_mac.sh scripts/stop_mac.sh`).
</details>
<verification>
Run from project root:
```bash
bash -n scripts/start_mac.sh && bash -n scripts/stop_mac.sh
```
Verify bash scripts pass syntax validation without error.
</verification>
</task>
